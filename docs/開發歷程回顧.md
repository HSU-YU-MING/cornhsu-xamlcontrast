# 開發歷程回顧 —— 從規劃書到 v0.1.0 公開發行

> 2026-07-30 ～ 07-31，兩天。本文是 v0.1.0 發行時的完整統整，
> 供接手者與未來的自己快速理解「每個設計為什麼長這樣」。
> 完整設計見 `../XamlContrast專案規畫書.md`，現況入口見 `../交接說明.md`。

## 起點

一份規劃書 v0.1、一支 457 行的 PowerShell 原型、三份基準線。核心命題：
**XAML 原始碼的對比度靜態稽核** —— 現有工具全是「執行期＋手動＋一次一個元素」，
這個反過來：不開 App、掃全專案、低於 WCAG AA 就讓 CI 紅燈。
`XamlContrast` 名字在 NuGet / npm / GitHub 都沒人佔。

整個專案的憲法：**稽核工具最大的風險不是漏報，是謊報健康。**

## 第一段：規劃書體檢

逐節審查抓出 14 個缺口，全數寫回文件：內部矛盾（M1 驗收要四專案但基準線只有三份、
「退化要用喊的」在 JSON 裡沒位置、基準線被原型 bug 汙染卻要當移植驗收）；
缺的合約（JSON summary、退出碼政策含「0 配對也要紅」、ignore 規格、config schema、
baseline ratchet 導入模式）。里程碑重排成 M0～M6。

## 第二段：M0 —— 先修工具再修專案

逐行審查抓到原型四個報告層 bug（規劃書 8.2）：Style 配對被 `$null -le 0`
靜默全判成裝飾、「低於 AA」把裝飾算進去、`.Count` 標題印空、`-ShowOk` 死碼。
修完重出基準線 —— **修好 bug 的瞬間，「已修好」的專案裡浮出一批被吃掉的真問題。**

## 第三段：M1 —— 色盤自動偵測

先探測四個專案的色盤長相，剛好四種形狀，直接定下偵測順序：
主題配對（QuillNest）→ C# 真相源（Kindling —— 關鍵規則
「**提供兩套主題的來源優先於只有一套的**」）→ 單一主題（CelFlow）→
無色盤退回寫死色碼並大聲喊（Cornea）。驗收：四專案零設定、輸出與寫死模式逐行一致。

## 第四段：M2＋M3 —— .NET 移植與輸出合約

回頭檢視改變策略：不逐位元組複刻即將丟棄的中文輸出，
**C# 直接實作最終合約（英文＋JSON），驗收用語意比對**。
最強的證據：兩個不同語言的獨立實作，在四個真實專案上數字完全一致 ——
含每筆 fail 的 file:line 與退出碼（`scripts/verify-baselines.ps1` 隨時可重跑）。

## 第五段：M4 —— 導入模式

baseline ratchet（凍結既有債、只擋新增與惡化；鍵不含行號防漂移、
記錄最差比值防**色盤漂移** —— 鍵是 `{DynamicResource Fg}` 字面文字，
色盤值調暗時鍵不變，少了比值欄位會靜默放行）；ignore 註解
（理由必填、壓掉計數、無效警告 —— ignore 不能變成新的靜默通道）。

## 第六段：工具與產品互相打磨

修正線與工具線形成回饋迴圈，**解析規則從 8 條長到 12 條**，每條都來自實查：

| 規則 | 來源 |
|---|---|
| 死 setter 過濾 | QuillNest CheckBox 誤報實查 |
| 具名/行內 Style 解析（BasedOn 揉平、同條件觸發器合併） | CelFlow 觸發態實查 |
| 停用態豁免（WCAG 1.4.3，計數不評分） | CelFlow 停用態假警報 |
| 半透明色票合成 | CelFlow BlueOverlay 假警報 |
| 模板根背景 | Kindling 驗收殘餘假警報實查 |

同時定案三類假警報形狀進盲區表：TargetName 模板 Setter、
跨元素同條件觸發器、（已修的）模板根背景。

## 第七段：三個產品修畢

| 專案 | 起點（真實數字） | 終點 |
|---|---|---|
| CelFlow | 破 39／偏低 57 | **0**（豁免 21，exit 0） |
| Kindling | 破 41／偏低 14 | 破 3（全為假警報類）／偏低 0 |
| QuillNest | 破 13／偏低 31 | 破 7／偏低 1（全為假警報類） |

合計 **250+ 處真實對比問題修畢**。插曲：Kindling 紗罩修正推翻了任務單的建議方向
（淺色的 Fg1 是深灰，紗罩要更淡不是更深）而且是對的 —— 數字讓推理可被驗證。

## 第八段：M5 —— 發行

工程師視角總檢視 → 修掉 `file` 改 root 相對路徑（同名檔撞鍵、跨 OS baseline 可攜）、
`--version`、`schemaVersion`、baseline 預設檔名、config 文件加「尚未實作」誠實標記。
骨架照 Parity：雙語 README、action.yml（先標 PR 行內註記再 enforce）、
ci.yml（**demo 預期 exit 1，跑出 0 就是守門員回歸**）、release.yml（Trusted Publishing）。
GitHub 公開、ubuntu CI 全綠、`v0.1.0` 44 秒發佈、從真實 NuGet 裝回來煙霧測試通過。

## 貫穿全程的三件事

1. **謊報健康零容忍**：前後八次「看起來健康但錯」的報告，每一次都變成回歸測試；
   所有放過的東西（豁免、排除、壓掉、解析失敗）都計數、都喊出來。
2. **段落完成就換角度回頭檢視**：每次自查都真的抓到東西 —— 路徑提示 bug、
   色盤漂移漏洞、文化相依解析、移植策略修正。
3. **治理決定入檔**：原型於 M5 後凍結（新規則 C# 先行）；1.0 前重新辯論預設 gate。
